# 会议纪要

把会议材料整理成可追溯的结论与可跟进的事项。只有录音文件时先核对宿主是否有真实转写能力；没有就请求转写文本，不把音频文件名当内容。

## 按目标选路

- 短摘要：交付讨论要点、已定决议、未决问题；用户没要表格时不用强制做双文件。
- 正式纪要：按 [纪要模板](references/minutes-template.md) 成文，按需制作 Word。
- 决议跟进/更新旧表：按 [行动项台账](references/action-tracker.md) 生成或更新 Excel；保留原编号、历史状态与用户修改，不重复新增同一事项。

## 提取与事实边界

记录会议名称、时间地点、主持/记录与出席范围；材料没有的信息标【待确认】，不为凑模板猜出席或请假原因。对长转写按议题分段抽取，并保留段落号、时间戳或用户原始行号作为来源定位。

将内容分为：事实与讨论、建议、明确决议、行动项、分歧/未决。只有明确达成的决定才写“会议决定”；“建议试试”“待领导确认”“基本同意但预算未批”保留原状态。原文含糊不能改成实名或确定日期；“尽快”保留并标期限待确认。

每个行动项含稳定编号、事项、负责人、协助方（如有）、期限、验收标准、来源定位；不把所有人默认成协助方。五要素缺失可先出草稿，集中列缺项；未定责任不能分配给记录人。相对日期用会议日期作基准，时区或基准缺失时不推算。

## 成文与跟进

按议题写背景、讨论要点、决议及关联行动编号；保留反对意见与待议事项，避免“大家一致认为”掩盖分歧。Word 和 Excel 使用同一份行动项数据，核对编号、责任、期限、状态一致。

对结构化行动项运行 [检查脚本](scripts/check.py)：

```text
python "<本技能目录>/scripts/check.py" "<输入.json>"
```

[接口与样例](references/validation.md) 说明完成率分母、空期限、取消项及销项校验。空输入和待确认项不能报告全部通过；自动检查只覆盖表中字段，不证明原文已作出决议。

## 交付核对

核对来源中的姓名、数字、决议状态及引用位置；缺项和互相矛盾的发言单列。更新已有台账时以编号合并，冲突保留双方值待确认，不静默覆盖或移动历史行。完成项需有销项依据/日期；取消项不算完成率分母，未完成的空期限不触发“逾期”。

Office 操作先发现宿主实际工具并查帮助，不固定工具名；文件模式可用已安装 python-docx/openpyxl，缺依赖时先给可用正文或 CSV 并说明。openpyxl 读到公式只证明公式存在，计算与视觉效果需 Excel/WPS/可用计算器复核。按请求交付文件、未决/缺项与实际检查范围，不自动分发会议材料。
